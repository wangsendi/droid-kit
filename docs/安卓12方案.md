**完整方案（先验证社区注入 → 再改 so）**

> 实现说明：官方 `redroid:12.0.0` 镜像本身不带 `camera.v4l2.so` 和 camera
> provider（已解包验证）。本仓库在 `camera/android12/` 中从 AOSP 12 编译这两个
> 组件，再严格按下面的 bind-mount 注入流程执行。详见
> `docs/CAMERA-ANDROID12.md`。

### 目标

让 Redroid 里的浏览器 `getUserMedia` 拿到一个看起来正常的摄像头（合理 label、facing、分辨率、capabilities），且不重新打包系统。

---

### 阶段一：先验证社区方案能跑通

**1. Host 准备视频源**

```bash
sudo modprobe v4l2loopback video_nr=10 exclusive_caps=1 card_label="Camera"

ffmpeg -re -stream_loop -1 -i input.mp4 \
  -vf scale=1920:1080,fps=30 -pix_fmt yuyv422 \
  -f v4l2 /dev/video10 &
```

**2. 从官方镜像抠出原版 HAL**

```bash
docker create --name tmp redroid/redroid:12.0.0-latest
docker cp tmp:/system/lib64/hw/camera.v4l2.so ./camera.v4l2.so
docker rm tmp

file ./camera.v4l2.so   # 确认是 ELF 64-bit
```

**3. 准备 manifest.xml**

从容器里先把原版拷出来，保留其他内容，确保有这段：

```xml
<hal format="hidl">
    <name>android.hardware.camera.provider</name>
    <transport>hwbinder</transport>
    <version>2.4</version>
    <interface>
        <name>ICameraProvider</name>
        <instance>legacy/0</instance>
    </interface>
</hal>
```

**4. 准备 linker 修复 rc（按需）**

`camera-ns-fix.rc`：

```rc
on property:apexd.status=activated
    exec -- /system/bin/sh -c "sed -i 's|namespace.default.search.paths = /vendor/|namespace.default.search.paths = /system/lib64:/vendor/|g' /linkerconfig/default/ld.config.txt"
    exec -- /system/bin/sh -c "sed -i 's|namespace.default.permitted.paths = /vendor/|namespace.default.permitted.paths = /system/lib64:/vendor/|g' /linkerconfig/default/ld.config.txt"
```

**5. 启动容器**

```bash
docker run -itd --privileged \
  --name redroid-cam \
  --device /dev/video10 \
  -v $(pwd)/camera.v4l2.so:/vendor/lib64/hw/camera.v4l2.so \
  -v $(pwd)/manifest.xml:/vendor/etc/vintf/manifest.xml \
  -v $(pwd)/camera-ns-fix.rc:/vendor/etc/init/camera-ns-fix.rc \
  -p 5555:5555 \
  redroid/redroid:12.0.0-latest \
  ro.hardware.camera=v4l2
```

**6. 验证**

```bash
adb shell dumpsys media.camera
```

浏览器里确认：

```js
navigator.mediaDevices.enumerateDevices().then((d) => console.log(d));
navigator.mediaDevices.getUserMedia({ video: true }).then((s) => {
  const t = s.getVideoTracks()[0];
  console.log(t.label, t.getCapabilities(), t.getSettings());
});
```

**阶段一通过标准**：能枚举到设备，能拿到画面。

### 阶段二：改 so 做成真实摄像头

**1. 参考源码**

```
hardware/libhardware/modules/camera/3_4/
```

在线地址：  
https://android.googlesource.com/platform/hardware/libhardware/+/refs/heads/main/modules/camera/3_4/

**2. 主要改这些**

- label 改成正常名字（例如 "Camera 0, Facing back" 或具体型号）
- facing 改成 `CAMERA_FACING_BACK` / `FRONT`
- 分辨率列表改成常见的（720p、1080p 等）
- capabilities 改成真实设备常见的
- 去掉所有明显虚拟痕迹（v4l2、virtual、loopback 等字符串）

**3. 重新编译**

只编译这个模块，得到新的 `camera.v4l2.so`。

**4. 替换注入**

用新的 so 替换阶段一里的文件，其他不变，重新启动容器验证。

### 最终结构

```
Host
  └── v4l2loopback (/dev/video10) ← ffmpeg
        ↓
容器
  ├── 你改好的 camera.v4l2.so  → /vendor/lib64/hw/
  ├── 修改后的 manifest.xml     → /vendor/etc/vintf/
  ├── linker 修复 rc           → /vendor/etc/init/（按需）
  └── ro.hardware.camera=v4l2
        ↓
浏览器 getUserMedia（看到正常 label 和 capabilities）
```
